0. SYNTHESIS RULINGS (contradictions resolved, with repo evidence)
=====================================================================
R1. A derived property is a RECIPE, not data (registry-first + user-first, unanimous over pipeline-first). Phase 1 puts NOTHING in the VTK pipeline: zero proxies, nothing to wipe, no lifecycle surgery. The ground-truth probes showed re-execution is survivable even for pipeline designs, but they do not rescue pipeline-first's foundation: `SourceRegistry.sync` (engine/sources/source_registry.py:411) hard-releases any ExtractBlockRepresentation not in its wanted set, and grids NEVER enter that set (line 429 skips IjkGrid rep types), so a registry-created grid isolate is torn down on the next Selectors commit. The recipe core avoids the whole class of problem.
R2. Identity = virtual path `derived://<rep_path>#<name>` (user-first), NOT tree-node paths (registry-first). Verified blocker for tree decoration in v1: the Data Explorer consumes `assembly_xml` = the serialization of the C++ collector's LIVE vtkDataAssembly, and `_refresh_assembly_xml` (app/boot.py:240) runs ONLY from `update_data_information` (line 294, i.e. on file add / ETP data-information events), never per Selectors commit. Registry-first's "tree is rebuilt each commit and decoration self-heals" does not match this repo: decorated nodes could die server-side on the next C++ assembly rebuild while the client keeps stale XML. Tree exposure is deferred (see phase 3+); every consumer works without it because all seams branch on `is_derived(path)` BEFORE any tree lookup. Rep paths cannot contain `#` (C++ MakeValidNodeName strips it), so `rsplit("#", 1)` parsing is safe.
R3. Unload lifecycle = KEEP recipes (user-first; all three judges flagged registry-first's def-dropping as its one real regression). Grid unloaded -> def flagged stale, value cache evicted, consumers fail soft with the existing notes; recheck revives it. Delete only on explicit user delete.
R4. Preview = in-panel stats strip + small Plotly histogram (user-first; judge 0's explicit instruction). Improvement over both parents: no preview subsampling. The cost of a preview is the INPUT block reads, not the numpy â€” you cannot subsample a pipeline read â€” so instead the LRU caches input arrays as well as results, previews compute at full resolution, and only bins/scalars cross the wire.
R5. MR/TS = forward (real_idx, ts_idx) per evaluation to every MR/TS input (registry-first + user-first; pipeline-first's frozen realization rejected). Deviation from both: offered realizations = INTERSECTION of the MR inputs' available indices, not union â€” a union pick missing on one input would fail at read time (`_resolve_vtk_name` suffixes a name `_get_named_array` cannot find); intersection makes every offered pick valid by construction. TS items = the global TimeKeeper list (what `axis_options` already builds).
R6. 3D coloring: primary = ONE session `@smproxy` DerivedPropertyAppender in the architecture-reserved `pv_plugins/fespp_trame_filters.py` (registry-first; TARGET_ARCHITECTURE.md line 36 MarkerCategorizer precedent, line 85 proxy budget). Fallback = the diff-style per-view isolate + PythonCalculator leaf (pipeline-first / user-first) â€” now GROUND-TRUTH-PROVEN: a PythonCalculator downstream of a raw `pvsimple.ExtractBlock` of the shared PDC computed a derived cell array over 926,808 cells, SURVIVED a FESPP re-execution (downstream recompute), degraded to 0 cells without throwing when the grid was fully unchecked, and the `inputs[0].CellData['<name>']` expression form handles arbitrary titles. User-first's client-side array injection into the collector output is REJECTED (least architecture-aligned, fights the wipe; both alternatives are better and one is already proven). Two probe-informed rules for the fallback: create the ExtractBlock RAW (never via `source_registry.get_or_create_extract_block` â€” see R1) and NEVER touch an `AssemblyName` property (this build's ExtractBlock has none â€” AttributeError; the default hierarchy extracts correctly from the selector `ctx.assembly_index.selector_for(rep_path)` returns).
