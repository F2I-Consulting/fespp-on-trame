# Refactoring Notes

Opportunities and code smells spotted automatically while documenting each
file (see the per-subsystem pages for context). Grouped by severity. These
are **suggestions for the fork**, not blockers — the app works as-is.

## ✅ Already done (on the `refactoring` branch)

A first "safe dedup" pass (behaviour-preserving) has been completed; the
per-file notes below still describe the *pre-refactor* state where they
overlap with these:

- **Two real bugs fixed** (on `dev`): the remote-file download signature
  mismatch in `__main__.py`, and the import-dialog multi-URL separator
  (`|` → `&`).
- **`inherit_display`** (threshold-output display inheritance) — was copied 3×
  (RepInScene / ExtractBlockRepresentation / IjkGrid) → now
  `sources/representation.inherit_display`.
- **Array introspection** (`available_arrays` / `array_data_range` /
  `_resolve_assoc`) — was copied 3× → now `sources/representation.
  arrays_from_source` / `array_range_from_source` / `resolve_assoc`.
- **Per-view routing** (target panel + pv_view + render/dual-push) — was copied
  across `slicer` / `slice` / `clip` / `threshold` dispatch → now
  `engine/view_routing.py`.
- **Threshold-chain logic** (single-upstream) — the graph walk + the
  show/hide rewiring shared by RepInScene + ExtractBlockRepresentation → now
  `sources/threshold_chain.py`. (IjkGrid's MULTI-upstream chain is genuinely
  different and was left as-is; the legacy ExtractBlockRepresentation half is
  slated for Phase-5 removal anyway.)
- **`_GROUPING_KINDS`** — was duplicated in `activator.py` + `tree_views.py`
  (to dodge a circular import) → now a single dependency-free leaf
  `core/node_kinds.GROUPING_KINDS`.
- **Dead `controller.view_replace`** bare-attribute no-op in `data_load.py`
  removed (the real refresh is the adjacent `view_update` flag).
- **Portable plugin path** — the hardcoded ExplicitStructuredGrid plugin path
  is now discovered under the ParaView install (`boot._resolve_esg_plugin`,
  with a fallback), so a fork on another PV version / OS still loads it.
- **`FesppMultiView` private reaches** — 8 external `mv._pv_internal` /
  `mv._html_views` / `mv._diff_panel_id` accesses (diff, boot, diff-colors
  dialog, orientation / transformation / camera widgets) now go through public
  accessors (`get_pv_view` / `get_html_view` + new `panel_pv_views` /
  `panel_html_views` / `diff_panel_id`). (`mv._panel_kinds` left — a smaller
  separate smell.)

Still open below: the larger structural splits (god objects), the remaining
cross-module private reaches (IjkGrid internals, `_panel_kinds`,
distribution↔stats privates), and the Phase-5 legacy removal.

## High priority

- **`fespp_on_trame/__main__.py`** — Remote-file mode calls download_file_from_url(url, epc_file_handle) passing an open file handle, but http_download.download_file_from_url expects a directory string (tmp_dir) and does Path(tmp_dir)/file_name. This will raise; remote mode appears broken. Reconcile the caller and the signature.
- **`fespp_on_trame/app/core/engine/boot.py`** — initialize_fespp_engine is ~1690 lines and holds dozens of inner closures (_refresh_distribution, _refresh_compare_stats, _refresh_compare_dist, _spawn_distribution_panel, _open_compare_stats, etc.). The stats/compare/distribution panel machinery alone is several hundred lines of closures and should be extracted into a dispatch module (e.g. distribution_panels.py / compare_panels.py) taking explicit deps, matching the pattern already used for data_load / visibility / active_array. The function is hard to navigate and the closures capture a large shared scope.
- **`fespp_on_trame/app/core/engine/boot.py`** — Hardcoded absolute plugin path '/opt/paraview/lib/paraview-6.0/plugins/ExplicitStructuredGrid/ExplicitStructuredGrid.so' is non-portable (breaks on any non-Linux / non-6.0 install) while the FESPP plugin path is parameterized via fespp_plugin_path. The ExplicitStructuredGrid path should be parameterized / discovered the same way.
- **`fespp_on_trame/app/core/sources/rep_in_scene.py`** — Documented god object: ~1235 lines owning source resolution, lifecycle, slice, clip, two parallel threshold-chain implementations (local non-IJK + IJK forwarding), wellbore-frame child management, per-view visibility, and snapshot/apply. The element_type delegation has peeled off per-kind behaviour but RepInScene still concentrates an enormous amount of orchestration. The threshold-chain local implementation (_add_threshold_local, _refresh_chain_visibility, _effective_input_for_parent, _has_visible_descendant, _inherit_display) is a near-verbatim duplicate of the same logic in extract_block.ExtractBlockRepresentation AND a structurally-parallel copy in ijkgrid.IjkGrid. Three copies of the chain algorithm.
- **`fespp_on_trame/app/ui/drawer/panel/solid_color_panel.py`** — SolidColorPanel.__init__ is ~530 lines and mixes UI construction, COE monkey-patching (overriding coe.get_representation_color_array_name and assigning controller.update_color_editor), per-view LUT resolution, marker color logic, and tree-chip computation. The nested closures (_resolve_coe_lut, _update_color_editor, _data_range_for_active_array) carry the heaviest logic and would be far more testable as module-level functions or a dedicated helper class.
- **`fespp_on_trame/app/ui/toolbar/dialog/import_dialog.py`** — Remote-URL parsing splits on '|' (remote_files_location.split('|')) but the field label and placeholder tell the user to separate URLs with '&'. Multi-URL imports silently break. Align the separator (parse on '&' or update the label).

## Medium priority

- **`fespp_on_trame/__main__.py`** — App.__init__ passes the raw `server` parameter to initialize_fespp_engine(server, ...) rather than self.server (the get_server(server, client_type='vue3') result). If the engine needs the vue3-configured server, this is an inconsistency. Verify against engine.py and pass self.server if appropriate.
- **`fespp_on_trame/app/core/activator.py`** — _GROUPING_KINDS is duplicated here from tree_views.py / C++ enum.h to avoid a circular import. This is a maintenance hazard (three copies must stay in sync). Consider a shared, import-safe constants module.
- **`fespp_on_trame/app/core/element_type/representation.py`** — Representation.ensure_extractor is ~80 lines mixing five concerns (Phase-2 guard, proxy creation, multi-view hide loop, display/scale/tint setup, legacy Z-fight hide) and is duplicated almost verbatim by FrameRep._create_child_extractor in frames.py (same clone/collector guard, same _create_plugin_filter_proxy + ExtractPath + multi-view hide + representation/scale/tint block). Extract a shared helper (e.g. _build_extractor(ris, extract_path, reg_name, hidden, z_apply, tint)) to remove the copy-paste and the risk of the two paths drifting.
- **`fespp_on_trame/app/core/element_type/representation.py`** — IjkGridRep.ensure_per_view_ijk reaches across layers to read legacy state: ctx.source_registry.get_ijk_grid(rep_path), then legacy._node_id / legacy._property_path (private attrs of another class). This tight coupling to IjkGrid internals means a refactor of IjkGrid's private fields silently breaks the per-view path. Expose a small public accessor on the legacy IjkGrid (e.g. current_property_path()) instead of poking _-prefixed attributes.
- **`fespp_on_trame/app/core/engine/active_array.py`** — toggle_dataarray_color is ~220 lines handling per-view map mutation, legacy mirroring, MR realization bookkeeping, implicit un-hide, channel show/COE-publish, ColorBy, and snackbar — too many concerns. The channel-specific branches (is_channel) are interleaved throughout; extracting a ChannelColorPolicy or pushing channel handling onto element_type/RepInScene would localize it.
- **`fespp_on_trame/app/core/engine/boot.py`** — initialize_fespp_engine is ~1700 lines and registers dozens of inline closures (distribution panel option watchers, compare-stats refresh, threshold/slice/clip/copy controllers, MR wiring). The stats/distribution/compare-matrix wiring (~lines 519-1085) is a large self-contained block that should be extracted to a stats_panel_wiring module to match the pattern already used for slicer/active_array/etc. boot.py should become a pure orchestration shell.
- **`fespp_on_trame/app/core/engine/boot.py`** — data_load.run is called with refresh_threshold_ui / push_active_ijk_state passed as keyword callbacks, while many other handlers call dispatch functions with positional (state, controller, server, _view, ...) tuples. The dependency-passing convention is inconsistent across dispatch calls (some take server, some take scene_registry, some take both registries) which makes the call sites noisy and error-prone. A small EngineContext dataclass bundling state/controller/server/view/tree/registries/activator would shrink every call site.
- **`fespp_on_trame/app/core/engine/data_load.py`** — data_load.run is a single ~240-line function doing 12 distinct stages. The IjkGrid pipeline-bump block (lines ~160-195) reaches into private IjkGrid internals (_src_extract_init, _all_slice_sources, _src_slicer_volume) directly; this couples the engine to IjkGrid's internal proxy layout. Expose an IjkGrid.force_full_update() method instead.
- **`fespp_on_trame/app/core/engine/data_load.py`** — Line 240 `controller.view_replace` is a bare attribute access with no call — dead code that does nothing (likely a leftover from a removed `controller.view_replace()` call). Remove or restore the call.
- **`fespp_on_trame/app/core/engine/data_load.py`** — run() is a 240-line procedure with 13 numbered phases and very heavy inline comments; the four _update_*_tracking helpers are already extracted but the main body still mixes PV pipeline orchestration, color-chip assignment, registry sync, and segfault-avoidance teardown. The IjkGrid slicer-bump block (lines ~160-195) reaches into private IjkGrid attributes (_src_extract_init, _all_slice_sources, _src_slicer_volume) — this belongs as a method on IjkGrid (e.g. ijk.force_full_pipeline()).
- **`fespp_on_trame/app/core/engine/diff.py`** — compute_diff reaches into FesppMultiView privates (mv._pv_internal, mv._html_views). The diff panel render is tightly coupled to multi-view internal attribute names; expose a public accessor (e.g. mv.views_except(diff_panel_id) and mv.html_view_for(panel_id)) so renaming internals doesn't break diff.
- **`fespp_on_trame/app/core/engine/distribution_dispatch.py`** — distribution_dispatch imports ~10 private (_-prefixed) helpers from stats_dispatch (_resolve_rendered_inputs, _append_if_multiple, _title_and_kind, _prop_kind_for_array_path, _rep_path_for_array_path, _resolve_vtk_name, _original_source_and_name, _default_real_idx, _ts_label_for_idx, _unit_for_array_path, _DEFAULT_ORIGINAL_ENTRY). Reaching across module privates is fragile coupling; promote the shared subset to a public stats_resolve API so a refactor of stats_dispatch internals can't silently break distribution.
- **`fespp_on_trame/app/core/engine/slice_dispatch.py`** — slice_dispatch and clip_dispatch are near-identical (publish_*_state, *_set, _resolve_active_panel_id, _resolve_rep, the offset_step = (hi-lo)/1000 math, the render+dual-push tail). The only deltas are the inside_out field and set_edit_mode. A single parametrized plane-dispatch helper (or a small base with a 'kind' arg) would remove a whole file's worth of duplication.
- **`fespp_on_trame/app/core/engine/slicer_dispatch.py`** — _render_and_push / _active_view_id / _target_panel_id panel-resolution logic is duplicated verbatim across slicer_dispatch, slice_dispatch, clip_dispatch, and threshold_dispatch (threshold_dispatch even copies _render_and_push inline to avoid importing the sibling). - **`fespp_on_trame/app/core/engine/state_defaults.py`** — Several state vars referenced/cleared elsewhere are not seeded here (ui_active_node_reservoir/surface/well cleared in hierarchy.py; solid_color_by_rep / solid_color_next_idx / _selector_rep_cache read+written in data_load.py; active_color_array_name / active_property_kind / empty_color_snackbar_* written in active_array.py; representation_active read in visibility.py). It is doing too much. Split into stats_compute.py (transient PV chain primitives), stats_resolve.py (tree/name resolution), stats_publish.py (table assembly), and stats_panel_state.py (mutators + cart) so distribution_dispatch's deep reach into _resolve_rendered_inputs/_append_if_multiple/_original_source_and_name targets a stable, narrow surface.

## Low priority

- **`fespp_on_trame/app/core/activator.py`** — _handle_reservoir_change is very large and interleaves PERF instrumentation (lambda _ms, many _ms_* locals, a try/finally print block) with real logic. The timing scaffolding obscures control flow and should be factored behind a small timing helper or removed for production.
- **`fespp_on_trame/app/core/element_type/base.py`** — The ElementType base defaults are a fully-functional standard Representation (REP eye, COLORABLE, STANDARD visibility, BUCKET_REP), yet base.py declares the child-management and source-construction methods as no-ops. This means the base is simultaneously 'the neutral contract' and 'a working standard rep minus the source builders', which is subtly inconsistent — the _FALLBACK is a Representation() not an ElementType(), so the base's rep-flavoured defaults are largely dead. Consider making base defaults genuinely abstract/raise, and keep the standard-rep defaults solely on Representation.
- **`fespp_on_trame/app/core/element_type/frames.py`** — visible_child_source and visible_child_displays both iterate the child store calling GetDisplayProperties + checking Visibility, differing only in what they collect (first match vs all displays). Could share one private generator _shown_children(ris) yielding (ext, display) to avoid the duplicated ParaView-import + loop boilerplate.
- **`fespp_on_trame/app/core/element_type/representation.py`** — rendered_sources / color_sources return either a list OR None-to-fall-through-to-legacy. This dual contract is a phased-migration smell that bleeds the legacy registry lookup into source_resolver.py; once Phase-2 fallback is retired, collapse to 'always return a list' and delete the None branches in source_resolver. Document or ticket the retirement so the two-tier contract does not become permanent.
- **`fespp_on_trame/app/core/element_type/representation.py`** — SeismicFrameRep is explicitly unverified ('Behaviour to be confirmed', kept on standard defaults) — flagged technical debt against TYPES_PARTICULARITES. A SeismicWellboreFrame may actually need frame-like folder/child behaviour; leaving it as a plain Representation could mis-render. Needs a spec decision before fork.
- **`fespp_on_trame/app/core/engine/active_array.py`** — The hardcoded French snackbar string 'aucune donnée à afficher sur cette représentation' is embedded in dispatch logic (line ~436) while the project maintains bilingual docs; user-facing strings should be centralized/localizable rather than literal in the engine layer.
- **`fespp_on_trame/app/core/engine/boot.py`** — _refresh_compare_stats imports compare_matrix twice within the same function body (once near the top for sorting/profile tags, again inside the CSV try-block). Dedupe to a single import at function entry.
- **`fespp_on_trame/app/core/engine/compare_matrix.py`** — highlight_annotations_for_items rebuilds baseline mode from scratch (out = {}; for mk in _METRIC_KEYS: ...) after already calling highlight_annotations, discarding the first result for baseline mode. The logic that maps metric->float/tag is duplicated between the two functions and between extrema/heatmap/baseline branches. Refactor highlight_annotations to accept either flat dicts or a metric-accessor callable so the wrapper need not re-implement baseline.
- **`fespp_on_trame/app/core/engine/compare_matrix.py`** — _csv_escape and _csv_num are duplicated across compare_matrix.py and distribution_dispatch.py with identical bodies (modulo .6g format string). Centralize in one csv_util helper.
- **`fespp_on_trame/app/core/engine/distribution_dispatch.py`** — _drill_to_inner is copy-pasted in distribution_dispatch and stats_dispatch (and the docstrings note a third copy lives in activator.py). Three independent copies of the vtkPartitionedDataSetCollection-unwrap. Hoist into a single engine.vtk_util module.
- **`fespp_on_trame/app/core/engine/etp.py`** — force_etp_refresh uses a fixed time.sleep(0.5) to wait for late ETP entries — a brittle timing hack that will both waste time on fast servers and still race on slow ones. Prefer polling GetLiveAssembly for a node-count change with a bounded timeout, or a server-side completion signal.
- **`fespp_on_trame/app/core/engine/panel_resolver.py`** — active_panel_id reads the private multi_view._active_panel_id attribute. Add a public accessor (e.g. multi_view.active_panel_id()) so the engine doesn't depend on a private field of the UI multi-view object.
- **`fespp_on_trame/app/core/engine/slicer_dispatch.py`** — apply_z_scale has a per-scene path AND a legacy fallback path that both iterate IjkGrid slicer sources, plus _collect_scene_proxies and _collect_legacy_proxies overlap with the proxy-collection done in source_resolver and visibility. The marker special-casing (is_marker_proxy + apply_marker_z) is applied twice (once in the generic proxy loop, once in an explicit _marker_extractors loop) which is redundant.
- **`fespp_on_trame/app/core/engine/slicer_dispatch.py`** — apply_z_scale runs the marker translate twice: once name-based inside the proxy loop (is_marker_proxy branch) and again via an explicit scene.reps() -> _marker_extractors pass. The second pass is redundant for any marker the first pass already handled; this is double work and double Render risk per scene. Consolidate into one pass keyed off the collected extractors, or document the intent as a deliberate backstop and skip extractors already translated.
- **`fespp_on_trame/app/core/engine/source_resolver.py`** — color_sources_for_rep_path and sources_for_rep_path have near-identical 4-branch fallback ladders (per-view element_type / legacy IjkGrid / legacy ExtractBlock / GetSources name-match). The legacy branches are duplicated; factor the shared legacy resolution into one helper to reduce drift risk.
- **`fespp_on_trame/app/core/engine/source_resolver.py`** — Repeated lazy `from trame.app import get_server` + `getattr(server.context, 'scene_registry', None)` boilerplate appears in _scene_rep_for_view, swap_to_scene_tfs, resolve_target_scoped_lut, target_view_and_panel, scene_lut_for_view. Extract a `_scene_registry()` / `_server_state()` helper to dedupe and centralize the context access.
- **`fespp_on_trame/app/core/engine/threshold_dispatch.py`** — on_threshold_pending_action takes the four threshold_* controller closures as positional params that shadow the module-level function names threshold_add/threshold_delete/etc. Inside the function, threshold_add refers to the parameter, not the module function — confusing and error-prone. Rename the params (e.g. add_cb, delete_cb) to avoid shadowing.
- **`fespp_on_trame/app/core/engine/vtk_log.py`** — capture_vtk_messages relies on a fixed time.sleep(0.05) to let the reader thread flush the pipe before slicing the queue — racy under load (a slow flush drops the tail of a session's messages). Consider a fd-drain barrier (write a sentinel marker to fd 2 and wait until the reader observes it) instead of a fixed sleep.
- **`fespp_on_trame/app/core/selector.py`** — The three select_node_* methods are near-identical (delete timeseries, walk selection, build path list, rebuild fespp_data_selectors, flip first_selection, set view_update). Extract a shared helper parameterized by the per-tab state var and companion-creation rules to remove triplicated code.
- **`fespp_on_trame/app/core/sources/etp_connector.py`** — connect()/set_dataspace()/get_dataspaces() use blocking time.sleep polling loops (up to 30s / 10s / 1s) on the server thread, which will stall the Trame server for the duration. Consider moving the async-wait onto a background task or exposing progress to the UI instead of a synchronous busy-wait.
- **`fespp_on_trame/app/core/sources/rep_in_scene.py`** — _arrays_from_source / _array_range_from_source are explicitly duplicated from ExtractBlockRepresentation 'so this module doesn't import from the soon-to-be-deprecated one'. - **`fespp_on_trame/app/core/sources/representation.py`** — Module docstring promises a Representation base class and shared ChainEntry that never materialised here (the ElementType hierarchy took that role instead). The file is now just 3 helper functions; the aspirational docstring is stale and misleading about the module's role.
