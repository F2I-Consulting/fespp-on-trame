# UI — Shell, Widgets and the Charter

> **Scope.** The shell around the dockview (`fespp_on_trame/__main__.py`: the top bar, the import door, the snackbars, the one dialog), the way a **widget** is packaged and wired, and the **charter** every widget is written in — the shared components of `widgets/_shared`, the rules R1–R18 they hold, and the three gates that keep them held (eslint, the browser sweep, strict mode). The panels and cards themselves are on [[UI — Content|UI-Content]].
>
> The page keeps its file name (`UI-Drawer-Toolbar-Shared`) for the links that point to it; the Vuetify drawer it once described is gone (2026-09).

## 1. The shell (`fespp_on_trame/__main__.py`)

A Vuetify `SinglePageLayout` in the F2I theme (primary `#00436D`, accent `#8FC31F`; the same blue is `--fp-accent` in the widgets). It is the only Python-drawn UI left besides the docked trees' frame, and it holds:

| Element | What | Bound to |
|---|---|---|
| The data tree's **layout** strip | Representation / Interpretation / Feature / Kind, one per view (`ui_tree_layout__<vid>`, `controller.tree_layout_set`), drawn by the widget over the same paths: nothing is unticked or read again. Interpretation and Feature come from attributes the plugin writes on a representation's top node. The grouping rows sit ABOVE a grid's container, never inside: properties stay general to the grid. | `view_doors`, `DataExplorerTree.byOwner` |
| One button per session panel | 3D views (go to one, show or hide each, and a new one), Explorer, Statistics, Calculator, Stratigraphy, Log view, Log ↔ Grid, Data health. Disabled until `ui_has_data`, and the tooltip says so ("— import a file first"). | `controller.open_<kind>` |
| Reload | Starts a new session after a `window.confirm` that says what is lost. | — |
| The browser's Back | While `ui_has_data`, the page keeps one history entry of its own (same address, marked `fespp-leave-guard`): Back lands on the page and a Warning asks (`fp-scrim` / `fp-dialog`, `data-fp-leave-guard`); Stay and Esc put the entry back, Leave goes back for real (and sets the guard again when there was no page behind). Client-side only: answered while the server is busy. | `LeaveGuard` (`widgets/session`) |
| **Import data** | The import door (`widgets/upload`, below). | `UploadData` |

All but the read in steps grey what lies under the app bar and hold it still (`fp-wait-scrim`, `data-fp-page-wait`). Inside a widget a wait is `FpProgress`, never another bar. | `data_load` |

### The import door (`widgets/upload`)

`UploadData.vue` is the button "Import data" and the modal it opens, holding **both sources side by side** (2026-09-22, `.up-sources`; they used to be two exclusive readings of an `fp-seg`, so a door labelled "Import data" opened on a drop zone and read as "files only" — nobody had a reason to press the second tab): **From this computer** (`UploadFile.vue` — drop or browse an `.epc` and its `.h5`, POSTed to the session's upload endpoint, `engine/io/upload_endpoint.py`, then loaded; one progress bar per file, and each says "read" or "failed") and **From an OSDU dataspace (ETP)** (`UploadOsdu.vue` — server URL, partition, token → Connect; the dataspaces → Load dataspace; Disconnect). The dialog is 860 px wide and stacks below 720 px.

**An empty session opens the door by itself**, once, on mount (`UploadData.mounted`, fed by `has_data` ← `ui_has_data`): with nothing loaded there is nothing to look at and every panel button of the top bar is disabled, so the one thing to do is import — the reader should not have to find the button first. Only on MOUNT and only while the session is empty: a door that came back on its own after being closed would be worse than one that never opened. The browser harness goes through `openImportDoor(page)`, which presses the toolbar button only when the door is not already open (pressing it on top of an open dialog hits the scrim, and the click never lands); `01-boot` asserts the door IS open on the empty session.

The files half also lists **what the session has already read** (`.uf-prior`), from `ui_loaded_files` through `UploadData`'s `loaded_files` prop — the same list Data health shows. The door is rebuilt on every open, so without it a reopened dialog came up empty however many files were in; and the reader never re-reads a path it was given once (`vtkEPCCollector` keeps every path it tried), so a name already there is a name a second drop will not load. Headless-free, browser-covered: `24-import-door`.

**Cancel** (`UploadFile.cancel`, `.uf-cancel`) aborts the XHR while its body goes up (`xhr.upload.onload` hides it: the server is reading by then, under the page's own wait); the batch leaves the list. The server writes each part to the temp dir under `received` from its first byte (`upload_endpoint._receive`) and removes them all when the request does not arrive whole, so a cut-off `.h5` never stays as "already imported" and a cut-off `.epc` is never read. Browser-covered: `24b-import-cancel` (Chromium, the upload slowed through the network conditions).

The ETP controllers (`etp_connect`, `etp_select`, `etp_disconnect`, `engine/etp.py`) are coroutines: a slow server blocks neither the state nor the other triggers, and the in-flight status (`etp_status`, `etp_connecting`) stays on screen until the answer. An error lands in `load_error`.

## 2. A widget

Every panel, card, tree and door of the application is a widget: one folder under `widgets/`, one npm package built once, one trame element class the Python mounts.

```
widgets/<name>/
  pyproject.toml                      the pip package trame_fespp_<name>
  README.md                           what it shows, its props and events
  trame_fespp_<name>/
    __init__.py                       __version__
    module/__init__.py                serve / scripts / styles / vue_use — what trame ships
    module/serve/                     the built bundle (committed for most widgets, .gitignored for a few)
    widgets/<name>_panel.py           class XPanel(AbstractElement): _attr_names, _event_names
  vue-components/
    package.json, vite.config.js      the UMD name
    src/main.js                       install(Vue): registers the root component globally
    src/<X>.vue                        the component (+ helpers)
```

- **Props and events.** `_attr_names` lists the props (`("empty_label", "emptyLabel")` maps the Python keyword to the Vue prop); `_event_names` the events, as tuples for a multi-word one (`("set_mode", "set-mode")`). An event must not bear a prop's name (`texture` prop + `texture` event = "keyword argument repeated" at mount; the event became `set-texture`). A Vue prop must not be named `style` or `class` (reserved).
- **Build.** `npm run build` in `vue-components` (copy `node_modules` from another widget — the build is offline); vite inlines `_shared/panel.css` into the bundle, so **an edit to `panel.css` or to a shared component means rebuilding every widget that imports it**, or two versions of the sheet ship in the same page.
- **Wiring.** The module must be enabled **eagerly** in `__main__.py` (`_modules`) — a panel or a card is created after the client has mounted — and the package listed in `setup/apps.yml` (`www_modules`, with the `.module` suffix) for the `www` bake; the Dockerfile installs every `widgets/*/trame_*` by glob. `_check_widget_bundles` fails the boot on a missing bundle; the browser harness fails on an unresolved tag.
- **The 23 packages**: shell — `upload`, `view-tools` (the vertical toolbar), `view-card` (the floating card frame); trees — `tree`; cards — `attributes`, `colormap`, `slicers`, `thresholds`, `volumetrics`, `timereal`, `display`, `navigation`, `camlink`, `globe`; panels — `compare`, `crossplot`, `welllog`, `reconcile`, `health`, `xmlviewer`, `stratigraphy`, `calculator`. Plus the third-party `trame_plotly` (the figures), `trame_color_opacity_editor` (the Colormap card's node graph) and `ptc` (the Camera card).
- **Mounted by Python, drawn by Vue.** The mount binds each prop to a state var (`data=("ui_reconcile", {})`, an expression `(f"ui_tool_target__{vid}['slicers']",)`) and each event to a controller (`set=(ctrl.compare_set, "[$event[0], $event[1]]")`) or a state write (`select="ui_strati_selected = $event"`); the host's own widgets (a plotly figure, the colour editor) go in the widget's default slot. A value with double quotes goes through a state var, never an inline attribute.

## 3. The charter

`doc/private/regles-ui-2026-09-13.md` (French, the PO's decisions of 13–14 September) is the reference; the rules, in short:

| | Rule | Held by |
|---|---|---|
| **R1** | A session panel wears ONE bar, always rendered: title → target → the controls that change what is shown → the right group (summary, action, export, tree button last). A second row is an `fp-subbar`. A 3D view has no bar: its chrome is the tab, the toolbar and the cards. | `FpPanel` slots |
| **R2** | One name at the three places: the top-bar button, the dockview tab, the `fp-title` — the `label` of `VIEW_KINDS`; a multi-instance kind is discriminated by its subject. | `views_config`, `MultiView.retitle` |
| **R3** | A panel that chooses its own content carries its tree, docked right (320 px), behind ONE button at the far right of the bar that shows whether it is open; closed by default except while the panel is empty, Statistics' open whenever the view opens. | `docked_tree.seed_open` |
| **R4** | A tick = the session's load, common to every view and the same in every tree (the PO, 18/10): ticked = read and kept; in a panel's tree it also puts what it read in that panel, in no 3D view. Unticking unloads from the session; when another view uses the object (a 3D view showing it, a panel holding it) the shared box asks first and names those views. | `tree_tick`, `_apply_selection(..., origin=)`, `app/scene/panel_trees`, `tree_grammar` |
| **R5** | The eye = "shown in THIS view": drawn in a 3D view; held by a panel (a row of the Statistics view, a well or a curve in the log, a row of the Log ↔ Grid table). Offered on what is loaded; it never reads. | `on_eye_changed`, `panel_tree_eye`, `compare_tree_eye` |
| **R6** | A folder's box ticks its visible descendants; its state is derived; the cost of a cascade is said before, never refused after. | `selection_deps`, `tick_confirm` |
| **R7** | One gesture whose cost exceeds what it shows asks first, in the application's one dialog, and reads nothing before the answer. | `ui_tick_confirm` |
| **R8** | An empty state says what the panel would show, the exact gesture that fills it, and why it cannot be made when that is the case; the gesture names a control that exists on screen. | `FpEmpty` (`shows`, `gesture`, `why`) |
| **R9** | An action past a second: its button disabled, what it holds greyed and held still under the bar (a view: `view_wait`; the page: the scrim of the pill, a read in steps holding nothing; a panel: `FpPanel busy`; a card or a row of its own: `FpProgress`), the previous content kept. | `_defer`, `FpProgress`, `FpBtn busy` |
| **R10** | Three severities, three channels: information in the summary or a chip glued to its control; a warning (something held back) and an error (an action failed, with the next step) as a full-width band under the bar, kept until its cause goes or the reader closes it. Never in the row of controls, never a chip for a sentence. | `FpNote`, `FpChip` (60-character cap on `warn`), `FpPanel` reads its `controls` slot |
| **R11** | One export: "Copy CSV" / "Copy XML", in the export slot before the tree button, clipboard else download — and it says which; disabled with its reason when there is nothing. | `FpExport`, `csvexport.handOver` |
| **R12** | What a tool acts on is named once: the card frame's target (`_set_tool_target`), or the accent chip after a panel's title. | `FloatingCard`, `FpPanel target` |
| **R13** | A segmented control holds two to four exclusive readings of the same data; the tree's type tabs and the XML explorer's document tabs are chrome, not segments. | `FpSeg` validator |
| **R14** | The summary is one sentence, first in the right group, "N of M …", wearing the warning form when something was left out. | `FpPanel summary`, `summaryDropped` |
| **R15** | One verb per act, imperative, Title case: Compute when nothing shows before it is asked, Refresh when the content exists. | `FpBtn label` validator |
| **R16** | A right-click is never mute: each tree declares the actions that mean something in it, and a node without one gets a disabled entry that says why. | `FpMenu` (the trees, the 3D view, Statistics) |
| **R17** | Select ▾ is offered in the data tree only. | `bulk_select` |
| **R18** | One vocabulary: `panel.css` and `tokens.css`, no private copy of a shared class, no colour written by hand, × and + as glyphs. | the eslint gate |

**The shared components** (`widgets/_shared/components`, documented in `widgets/_shared/README.md`): `FpPanel`, `FpBtn` (title required, label in Title case), `FpSelect` and `FpSeg` (one option shape `{value, label, title?}`, `FpSelect` drawing `done` too: a green ✓, the option's result already there; a list
always draws its own chevron in `panel.css`, a page reset hiding the native
arrow, and with nothing to choose — one option a reader can take, already
the value, no greyed option — `FpSelect` is the option's words, `.fp-sel-one`), `FpNum` (never `type="number"`: a text field with a decimal keypad, a typed comma read as the point, the value written back exactly), `FpChip` (not a control; what is pressed goes in its `after` slot), `FpNote`, `FpEmpty`, `FpExport`, `FpMenu` (the one right-click menu: Escape and a click beside it close it, it flips back from the edges, a disabled entry keeps its reason; an entry's `icon` — "fespp-<name>" or "mdi-<name>" — stands in a column of its own), `FpHistOptions` (the one form of a histogram's options, `compact` for a bar that shares its width), `FpTransport` (the one stepper of time steps, realizations and cross-plot tracks), `FpRange` (the one slider, `single` for one value; the lint gate refuses a raw `<input type=range>`); `fp-busy` is the one activity bar. Each holds its rule as a required prop with a validator AND an `incomplete` computed that raises `data-fp-incomplete` and renders a visible accusation, because a production build strips validators. They are imported by relative path and registered locally in each widget (no runtime-shared package: a load order between bundles would break the harness that mounts them one at a time). `numfmt.js` and `csvexport.js` are the two helpers every widget writes numbers and files with; `engine/utils/numfmt.py` and `csv_export.py` are their server-side twins.

## 4. The three gates

1. **eslint** — `sh widgets/lint.sh` (`widgets/.eslintrc.widgets.json`, run by `test-browser.ps1`): in a widget, a raw `<button>` or `<select>`, an `<input type="number">` (or a bound `:type`), a class ending in `-empty`, `fp-btn` written by hand and any `f…-(btn|header|head|bar|chip)` private copy are errors, and an `fp-*` component written but not imported is one too. Two PERMANENT lists carry the exceptions with their reason: the shared components themselves, and the chrome that is not the charter's buttons (the card frame, the toolbar rail, the tree's rows and menus, the XML explorer's document tabs and breadcrumb — for these the rule is narrowed to refuse the `<select>` only, never switched off). The pending list of files not yet converted emptied on 2026-09-16 and does not come back: a widget that must draw a refused shape goes on a permanent list, with its reason.
2. **The browser sweep** — `tests/browser/specs/04c-components.spec.mjs` opens every panel and every card and reads, in one pass: the tags Vue left unresolved, every `data-fp-incomplete`, every `.fp-empty` (its `data-fp-shows` / `data-fp-gesture`, and the quoted words of its gesture looked for in the same panel), every `.fp-note` (severity, ×, next step), every `.fp-btn` (tooltip, Title case), every `.fp-right` (summary first, tree button last), every `.fp-seg` (two to four), every `input[type=number]`, and a note found in a bar. Its ledgers are empty since 2026-09-16; a regression is a new line in the diff.
3. **Strict mode** — `FESPP_STRICT=1` (armed by both harnesses): `engine/strict.py` reports every exception a silent `except` swallows, and `tests/unit/test_silent_handlers_ratchet.py` holds the count of silent handlers per module from growing.
